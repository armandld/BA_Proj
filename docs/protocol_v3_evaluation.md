# Q-HAS evaluation protocol (V3) — pre-registered

**Status:** frozen before any new computation. Any deviation must be logged in
`docs/protocol_deviations.md` with a justification.
**Goal:** decide, with referee-proof methodology, whether a local-Ising /
QAOA refinement criterion has value beyond the classical multi-indicator
baseline — and if not, state precisely *what* fails (representation,
selection, prediction, or closed-loop behaviour).

This protocol supersedes the ad-hoc evaluation choices of the V2 study
(static top-25% label, block-max aggregation, GBT-as-supremum, snapshot-level
bootstrap). Existing phases are mapped to it in §7; most are reused.

---

## 0. Design principles

1. **Three nested levels**, cheapest first. Each answers ONE question.
   A lower level can only *rule out*; only Level 3 can *rule in*.
   - L1 (static): is the instantaneous feature information sufficient?
   - L2 (predictive): does temporal information add value at horizon h > 0?
   - L3 (closed-loop): does any of it matter inside the running pipeline?
2. **Continuous quantities first, thresholds second.** Binary labels and F1
   are reported only as secondary, robustness-checked views.
3. **Claims about families require either a proof or an exhaustive search —
   never an ERM learner.** A learner's out-of-distribution score is a
   statement about the *selection procedure*, and is reported as such.
4. **The unit of statistical replication is the trajectory** (one scenario ×
   Re × physics seed), never the snapshot.
5. **All headline numbers come from one tagged commit**, regenerated by one
   script. Both score aggregations (block_avg, block_max) are always
   reported side by side.

## 1. Common ground (data, labels, baselines)

### 1.1 Data
- Scenarios: the 4 current classes (OT, Harris tearing, KH, MHD rotor)
  **plus** the already-implemented Lamb–Oseen, island coalescence, double
  tearing, magnetic twist → 8 LOSO folds minimum.
- Re = Rm ∈ {400, 800, 1200, 1600}, N = 256, validated by phase 1b checks
  (div B, OT energy-decay window, KH growth) on every new trajectory.
- **Physics seeds: ≥ 5 per (scenario, Re)** — perturbed initial conditions
  (amplitude noise at the V1 perturbation level). The current single-seed
  dataset is kept only for cross-checking against published V2 numbers.

### 1.2 Quantities and labels
- **Primary quantity (continuous):** per-patch coarsening error
  `e_i(t)` as defined in phase 2 (`patch_l2_errors`), kept continuous.
- **Secondary quantity (dynamic, new):** per-patch *evolution* error
  `d_i(t; δt)` = L2 distance at t+δt between (i) the field evolved at full
  resolution and (ii) the field evolved with patch i held at coarse
  resolution (all other patches fine), normalised as in phase 2. This is the
  V1-style ground truth, computed offline. δt = one hybrid step (0.1).
- **Binary views (secondary only):** `y_i = 1{e_i > P_p}` with p = 75
  headline and p ∈ {60,…,90} sweep (phase 2b reused). Prevalence is fixed by
  construction (1−p); every table involving a binary label states it.

### 1.3 Baselines (mandatory in every table)
- B1 classical score, **block_avg** aggregation (V1 convention).
- B2 classical score, **block_max** aggregation (V2 convention).
- B3 refine-all and refine-none (degeneracy floors; any method within 0.005
  of a floor is flagged "degenerate" and excluded from win/loss counts).
- B4 GBT on all 9 features (ERM reference).
- B5 GBT on `score_classical` alone (1 feature) — separates "feature basis
  insufficient" from "ERM selects non-transferable features".
- B6 learned linear H (phase 11c).
- B7 random ranking (for ranking metrics).

### 1.4 Metrics
- **Primary: captured-error-at-budget.** Rank patches by the method's score;
  refine the top k where k/n = budget b; report
  `CE(b) = Σ_{i∈top-k} e_i / Σ_i e_i` for b ∈ {0.10, 0.25, 0.50}, plus the
  full CE(b) curve and its AUC. This is threshold-free, matches the V1 cost
  trade-off, and has no degenerate optimum.
- Secondary: Spearman ρ between method score and e_i (or d_i).
- Secondary: F1 at the p75 label, with degeneracy flags (§1.3 B3).
- L3 only: trajectory metrics — relative L2 vs DNS at fixed compute budget,
  compute at fixed L2, IoU patch stability, captured fraction (V1 Table 8.2
  metric set).

### 1.5 Statistics
- **Block bootstrap at trajectory level** (resample trajectories, B = 1000),
  percentile CIs. Snapshot-level resampling is forbidden for headline claims
  (temporal autocorrelation).
- Paired comparisons: per-trajectory deltas; report mean Δ, 95% CI, and the
  fraction of trajectories with Δ > 0. Holm correction across scenarios.
- Effect sizes with |d| > 1 require ≥ 10 trajectories before being quoted.

## 2. Level 1 — static sufficiency (repaired V2)

**Question Q1:** how much of the continuous coarsening error e_i is
recoverable from instantaneous local features — within distribution, and on
a held-out instability class?

- **Splits:** (a) *temporally blocked* within-scenario split (train t < t0,
  test t > t0, t0 = 60% of each trajectory) — replaces the random split,
  which leaks near-duplicate snapshots; (b) LOSO over ≥ 8 folds; (c) the old
  random split is computed once, only to quantify the leakage gap.
- **Models:** B1–B6 plus GBT with forward feature selection under LOSO
  (which features transfer?), and a stencil GBT (45 features) under (a)
  only — under LOSO it is reported as "ERM stencil", never as a ceiling.
- **Information-cone curve:** k-hop stencil GBTs for k ∈ {0,1,2,3}
  ((2k+1)²×9 features), blocked split and LOSO. This measures whether the
  ceiling grows with neighbourhood radius — the empirical test of the
  "larger VQA grid → larger useful cone" scaling hypothesis. Decision rule:
  if the curve is flat (Δ ≤ 0.01 per hop, current k=1 evidence), the cone is
  retired as a scaling axis in the manuscript; if it rises, the slope is
  reported as the quantitative case for larger grids.
- **Decision rules (pre-registered):**
  - If B5 (score-only GBT) ≈ B1/B2 under LOSO while B4 collapses → the
    failure is ERM feature selection under shift, not feature insufficiency.
    This becomes the headline mechanism.
  - If even B5 collapses under LOSO → threshold/scale transfer failure;
    investigate per-scenario score normalisation before concluding.
  - "Feature sufficiency" claims are made ONLY from the temporally-blocked
    joint fit (train on all scenarios), never from LOSO.

**Theory deliverables attached to L1:**
- Proposition 1 (mean-field reduction) kept as is.
- Proposition 2 restated **conditionally**: if for every site i,
  `Σ_{j∋i} 2|J_ij| + Σ_{p∋i} 4|K_p| < |h_i|`, then the exact ground state is
  s_i* = −sign(h_i) (no collective flip is energetically favourable), hence
  the decision is strictly per-site. Numerically report the fraction of
  sites satisfying the condition for the V1 and V2 Hamiltonians.
- All "ceiling" language replaced by "selection" language: the bound applies
  to coefficient functions *selected by training on seen classes*.

## 3. Level 2 — predictive value (new; the fair test of φ/ψ)

**Question Q2:** do temporal features anticipate hardness that instantaneous
features cannot see?

- **Task:** features at time t → predict e_i(t+h) (continuous) and
  y_i(t+h), for horizons h ∈ {1, 2, 4, 8} × snapshot_dt.
- **Temporal features:** (i) signed ψ from `compute_psi_v2` (parameter-free);
  (ii) signed ψ with V1 trial-#4 β = 9.94 (NOT trial 85); (iii) finite
  differences of the 9 features over one step. Never |ψ|.
- **Key subset analysis:** patches that are *easy now, hard at t+h*
  (y_i(t)=0, y_i(t+h)=1). Report CE(b) and recall on this subset
  specifically — this is the only place anticipation can show up.
- **Metrics:** CE(b) at horizon h; lead-time curve (max h at which the
  method still captures ≥ x% of future-hard patches at budget b);
  Δ(with-ψ − without-ψ) with trajectory-level CIs.
- **Decision rules:**
  - ψ adds nothing at any h, any split → the anticipation claim of V1 is
    retired, with a fair test on record.
  - ψ adds value within-scenario but not LOSO → anticipation exists but its
    calibration (β) is scenario-specific; report both.
  - ψ adds value under LOSO on the easy-now-hard-later subset → headline
    positive result; escalate to L3 immediately.

## 4. Level 3 — closed loop (the only decisive level)

**Question Q3:** does the decision engine change trajectory-level outcomes
when it runs inside the V1 pipeline (TTL, warm-start, feedback through the
solved state)?

- **Protocol:** LOSO at the pipeline level. For each held-out scenario:
  train the V1 hyperparameters (same Optuna budget as V1, frozen at 170
  trials) on the other scenarios' composite loss; run the full V1 pipeline
  (Q-HAS and classical arms, identical seeds/solver/TTL) on the held-out
  scenario.
- **Runs:** 8 folds × 3 physics seeds × 2 arms at Re = 400 (V1 regime),
  plus 1 fold (OT) at Re = 1600 as a stress check. Fixed wall-clock budget
  per run; wall-clock is itself recorded and reported.
- **Metrics:** V1 trajectory set (§1.4) + CE(b) of the realised refinement
  masks against the dynamic GT d_i.
- **Decision rules:**
  - Classical ≥ Q-HAS on L2-at-budget on ≥ 6/8 folds with CI excluding 0 →
    falsification is complete and closed-loop; strongest possible negative.
  - Q-HAS wins only on folds where L2 wins predicted it → levels are
    consistent; the static analysis is validated as a proxy.
  - Q-HAS wins on folds where L1/L2 predicted loss → closed-loop dynamics
    (TTL, feedback) carry value the static analysis cannot see; this becomes
    the central result and L1 claims are scoped accordingly.

## 5. Reporting rules

1. Every table lists B1–B3 and flags degenerate operating points.
2. No metric, split, or subset may be introduced after results are seen
   without a logged deviation entry.
3. Both aggregations (avg/max) in every score-based row.
4. Single source of truth: `study/run_study_v3.sh --all` regenerates every
   number from the tagged commit; the manuscript cites only that output.
5. Negative results are reported with the same prominence as positive ones.

## 6. Success criteria for the paper

The paper is publishable under ANY outcome, with narrative fixed in advance:
- All three levels negative → "A three-level falsification of local-Ising
  refinement criteria for MHD AMR", with the selection theorem and the
  inductive-bias inversion (flexible models collapse OOD, physics priors
  transfer) as the mechanism.
- L2 positive, L3 negative → anticipation exists but is destroyed in the
  loop; report both, diagnose (stability? TTL interaction?).
- L3 positive anywhere → scoped positive result with the static bounds as
  honest context.

## 8. Implementation brief

This section turns §1–§7 into an executable work plan. The protocol above
is the specification; this section is the contract for the implementation.

### 8.0 How to work

1. Commit this file as `docs/protocol_v3_evaluation.md` BEFORE any code
   change, and create `CLAUDE.md` at the repo root containing §8.1 + §8.2.
2. **One task per session, in order.** Begin each session with: "Read
   docs/protocol_v3_evaluation.md §8.1–§8.2, then execute Task N. Propose a
   plan and the list of files you will create/modify; wait for my approval
   before writing code."
3. End each session by running the task's acceptance command, appending the
   numbers to `study/v3/RESULTS.md`, and committing as `v3-task-N: <summary>`.
4. If a task requires anything not specified here, stop and ask — never
   improvise a metric, label, split or subset (§5.2).

### 8.1 Context block

> This repository (BA_Proj) contains Q-HAS: a hybrid quantum-classical AMR
> framework for 2D MHD. `src/` is the V1 production pipeline (MHD solver
> FD4/RK4 in `src/Simulation/`, QAOA stack in `src/VQA/`) — frozen, working,
> covered by `run_tests.sh`. `study/` is the V2 falsification study: a batch
> pipeline (phases 1→13) that generates DNS snapshots, defines a per-patch
> "hard to coarsen" label, builds Ising Hamiltonians from physical features,
> and bounds the approach with ML surrogates (GBT) under random-split and
> leave-one-scenario-out (LOSO) evaluation. The V3 work plan
> (docs/protocol_v3_evaluation.md) repairs V2's evaluation layer: continuous
> metrics, blocked/LOSO splits, trajectory-level statistics, a predictive
> level, and a closed-loop level. Key entry points:
> `study/config.py` (constants), `study/phase2_hard_patches.py` (labels),
> `study/phase4_exact_diag.py::build_patch_hamiltonian` (fields→Hamiltonian),
> `study/phase11_upper_bound.py` (features, dataset, models),
> `study/phase11b_loso.py` (LOSO), `src/Simulation/HamiltParams_v2.py`
> (V2 coefficients + `compute_psi_v2`), `logs/FINDINGS.md` (published V2
> numbers, the regression reference).

### 8.2 Global guardrails (non-negotiable)

- **V1 is read-only.** Never modify `src/` (solver, grid, refinement,
  PhysToAngle, HamiltParams, VQA) unless a task explicitly lists the file.
  `bash run_tests.sh` must pass unchanged after every task.
- **V2 phases are read-only.** All new code lives in `study/v3/` (a new
  package). When a task "repairs" a phase, copy it into `study/v3/` and
  modify the copy; the original must remain runnable for regression.
- Every task ships: code + a pytest under `tests/v3/` + an entry in
  `study/v3/RESULTS.md` (command, git hash, numbers).
- Determinism: every new script accepts `--seed`, and writes the git commit
  hash and full CLI args into its `.npz` outputs.
- Reuse before rewriting: import `build_dataset`, `extract_features_2d`,
  `make_model`, `fit_eval`, `best_threshold_f1` from
  `study/phase11_upper_bound.py`; import the solver, never re-implement
  numerics.
- French comments are fine; code identifiers and RESULTS.md in English.

### 8.3 Task list

**Task 0 — Regression baseline (gate for everything else).**
Goal: reproduce the published V2 numbers from data so later diffs are
attributable. Run `phase11_upper_bound.py` and `phase11b_loso.py` at N=256,
dim=4 (regenerate phases 1–2 data via `run_study_v2.sh` if `study/results/`
is absent — hours of DNS).
*Accept:* per-fold LOSO F1 match `logs/Result_phase11b.txt` (GBT fit is
deterministic per phase 11f); classical 0.434, site GBT 0.189 (±0.001).
Record any mismatch verbatim before proceeding.

**Task 1 — B5 score-only GBT + forward selection under LOSO (§2, decision
rule 1; the single most decisive cheap experiment).**
New: `study/v3/t1_feature_selection.py`. Using the exact LOSO folds of
phase 11b: (a) GBT restricted to the `score_classical` column; (b) greedy
forward selection (start empty; at each step add the feature maximising
mean LOSO F1; stop at 9). Output: table feature-set → per-fold F1 → mean.
*Accept:* full-9 row reproduces 0.189; B5 row present; RESULTS.md states
which of the two §2 decision-rule branches the outcome selects.

**Task 1b — Information-cone curve (§2; tests the "more qubits = larger
useful neighbourhood" scaling hypothesis classically).**
New: `study/v3/t1b_cone_curve.py`. Generalise `stencil_features` from
`phase11_upper_bound.py` to k-hop neighbourhoods (periodic `np.roll`
shifts): k ∈ {0,1,2,3} → 9, 45, 225, 441 features. Fit GBT per k under
(a) the Task-4 blocked split and (b) the phase-11b LOSO folds; plot/print
F1 (and CE(b) once Task 2 exists) vs k. Guard against the
sample-to-feature ratio at k=3 (report n_train/n_features; if < 20, also
fit with `max_features` capped and flag).
*Accept:* k=1 LOSO row reproduces the published stencil 0.215 (±0.001);
the curve and its per-hop deltas are in RESULTS.md with the §2 decision
rule applied (flat → cone retired; rising → slope quoted).

**Task 2 — Metrics module.**
New: `study/v3/metrics.py`: `captured_error_at_budget(scores, e, budgets)`
returning CE(b) for b∈{0.10,0.25,0.50} and the CE curve AUC (rank by score,
take top-⌈bn⌉ patches, sum their e over total e); `spearman(scores, e)`;
`degeneracy_flag(pred, prevalence, tol=0.005)` implementing §1.3-B3.
*Accept:* pytest with hand-computed 6-patch examples; refine-all and
refine-none floors verified analytically (F1 = 2p/(1+p) and 0).

**Task 3 — Trajectory block bootstrap.**
New: `study/v3/stats.py`: `bootstrap_by_trajectory(values, traj_ids, B=1000)`
and a paired-delta variant (resample trajectory IDs with replacement,
recompute the metric per resample, percentile 95% CI). *Accept:* pytest on
synthetic data with known sampling distribution; demonstrates wider CIs than
snapshot-level resampling on autocorrelated synthetic input.

**Task 4 — Temporally blocked split (§2a).**
New: `study/v3/t4_blocked_split.py` (copy of phase 11 evaluation loop):
train on the first 60% of each trajectory's snapshots, validate on the last
40%, per (scenario, Re). Recompute B1–B6 with Task-2 metrics, dual
aggregation (block_avg AND block_max baselines — block_avg requires adding
an aggregation switch to the score extraction, mirroring
`phase11e_v1h_loso.py`'s `_block_avg`). Print blocked vs old random split
side by side (the gap = leakage quantification, reported once, §7).
*Accept:* one table; random-split numbers match Task 0.

**Task 5 — Phase 11E rerun, fixed (§3 prerequisite; retires or revives ψ).**
New: `study/v3/t5_v1_psi_loso.py` (copy of `phase11e_v1h_loso.py`). Changes:
(1) V1 parameters from `study/config.py` `TRAINED_*` (Optuna trial #4,
β=9.94, thr=0.1496) — keep the hardcoded trial-85 run as a comparison arm,
and log the discrepancy; (2) **signed** ψ: `score_aug = clip(score +
0.5·sin(ψ), 0, 1)` (sign preserved: damping reduces urgency), plus the

bootstrap. *Accept:* 2×2×2 comparison table (params × ψ-handling ×
aggregation); RESULTS.md states whether "ψ does not transfer" survives.

**Task 6 — Dynamic ground truth d_i (§1.2; the only heavy new code).**
New: `study/v3/t6_dynamic_gt.py`. For snapshot t, patch i: build a field
variant where patch i alone is block-averaged to patch resolution and
prolonged (reuse `coarsen_field` logic restricted to the patch window);
evolve BOTH reference and variant with `MHDSolver.step_full` for δt=0.1
(same CFL dt sequence); `d_i` = relative L2 difference of the full fields at
t+δt, normalised as in phase 2. **Pilot first:** N=128, one config, 2
snapshots, all 16 patches; report wall-clock in RESULTS.md and project the

Output `.npz` mirrors the phase-2 format so phase-11 builders accept it as a
drop-in label source. *Accept:* pilot completes; sanity check
Spearman(d_i, e_i) > 0 reported.

**Task 7 — Predictive dataset, Level 2 (§3).**

variants from Task 5) + one-step finite differences of the 9. Targets:

report CE(b) and subset recall, blocked split + LOSO, Task-3 CIs.
**Causal-cone cross:** rerun with the Task-1b k-hop feature sets, k ∈
{0,1,2}, at every horizon h — the radius at which performance saturates
should grow with h if hardness is advected from upstream neighbours
(expected scale: k* ≈ v·h/Δx_patch). Report the k×h matrix; this is the
physically grounded version of the information-cone hypothesis and a
candidate headline figure.
*Accept:* lead-time table per §3 plus the k×h matrix; decision-rule branch
stated.
